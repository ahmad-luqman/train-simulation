# Phase 7 — release readiness

## Implementation plan

1. Preserve the current miniature railway interface and all simulation safety assertions. Add a save library with three manual slots, three rotating autosaves, a recovery copy before replacement, portable JSON and detached validation. Use two atomic generations per slot so an interrupted write or corrupt newest generation can recover without deleting legacy saves.
2. Add a system-aware reduced-motion preference, keyboard map movement, visible focus, readable controls, responsive scrollable dialogs and non-color signal cues. Keep game motion and safety rules authoritative.
3. Freeze simulation and sound on WebGL context loss; resume rendering on restoration with the railway paused. Stop hidden-tab rendering and reset frame timing on resume. Isolate optional portrait failures from scene startup.
4. Expose bounded real frame-time and CPU-submission measurements, resource counters and downloadable reports. Measure before optimizing; do not label headless timings as GPU evidence or expand the twelve-service capacity to meet an obsolete provisional benchmark.
5. Run storage fault/recovery tests, full existing physical/economy/region regression, long-session stress, typecheck, lint and production build. Record browser acceptance and hardware limits separately. Preserve campaign balance until observed player evidence justifies changes.

## Acceptance log

Runtime hardening is implemented. Automated evidence and the remaining browser/device, first-time-player and independent-review gates are separated below.

## Delivered behavior

- **Save library:** three named manual slots, three rotating autosaves and a recovery slot. Each slot retains two checksum-protected generations. Writes complete only after an IndexedDB transaction commits; a quota error or interrupted transaction preserves the previous copy. Supported browsers coordinate writers with Web Locks, with an in-tab queue as fallback. Rotation uses sequence counts rather than the system clock. A full simulated-hour library exceeded 6.9 MB in the stress run, which is why the new library uses IndexedDB instead of localStorage.
- **Recovery and portable files:** load validates detached geometry, physical authority, economy, fleet and region before replacing anything. Invalid newest generations fall back to an intact previous generation. Loading pauses the railway and first copies the current state to Recovery; starting a new railway also keeps a copy by default. A visible opt-out lets the player continue when storage is unavailable, after exporting any progress they want to keep. Imported files are limited to 16 MB. Manual overwrites and replacing the current railway require an in-game confirmation. Legacy localStorage slots are never overwritten.
- **Real legacy migration fix:** frozen saves generated by actual v5/v6 commits exposed the mountain expansion's incorrect requirement that all fourteen towns exist in an old eight-town save. Migration now adds an explicit `network.baseline: 'valley'` marker, retaining the original protected eight towns/thirteen corridors, custom construction, every physical train record and cash. Resaving keeps the portable format at v8. The normal alpine baseline remains required for unmarked v8 saves; unknown baseline markers, missing protected track and malformed saves still fail atomically. Historical v5–v8 fixture origins are recorded in `lib/railway/fixtures/README.md`.
- **Autosave:** every 120 active wall-clock seconds while visible, running and outside photo/context-loss states. Pauses, hidden tabs and photo mode do not count toward the interval. The timer resets on new/load. Failed autosaves display a device-storage message and preserve earlier copies. Autosaves do not silently replace the running game on startup.
- **Accessibility and input:** focused-map arrow panning and +/− zoom, deliberate one/two-finger camera mappings, suppression of accidental train selection after multi-touch gestures, office focus entry and return with Escape, visible focus rings, larger primary controls, coarse-pointer target sizing and scrollable dialogs. Signals supplement lamp color with vertical proceed/horizontal stop arms. Reduced motion initializes from the system setting, follows system changes until explicitly overridden, and persists an explicit choice. It stops decorative particles, sway, animated water/lighting and animated camera transitions without changing railway physics or weather rules.
- **Lifecycle:** hidden tabs skip rendering and reset the frame clock on return. Context loss freezes simulation and silences audio; successful context restoration reapplies graphics settings and leaves the railway paused. Optional portrait errors no longer prevent scene readiness, and portrait rendering releases its temporary graphics context even after failure. Successful portraits are reused on remount.
- **Measurement:** the Atmosphere dialog exposes and exports the latest 1,800 frame samples with p50/p95/p99 frame intervals, p95 CPU submission cost, draw calls, triangles, geometry/texture counters, particles, quality, camera and viewport. Frame stalls are recorded before timestep clamping. CPU time includes simulation and render submission, not GPU execution. Reports can be reset for each acceptance scene.

## Automated evidence

- **115/115 regression tests pass** after the final migration fix (90.5 seconds, 11 September 2026), retaining all previous 105 tests. **Typecheck, lint and production build pass.** The existing client-bundle-size and Vinext route-classification warnings remain.
- New coverage includes independent manual slots, portable round trips, quota/interrupted writes, corrupt and semantically invalid newest generations, asynchronous transaction completion/failure, autosave isolation, preserved legacy slots, frozen historical v5–v8 migration, atomic malformed-layout rejection, bounded performance samples and reduced-motion camera acquisition.
- `npm run benchmark:release -- docs/benchmarks/phase7-release.json` completed **3,600 simulated seconds** with all twelve trains, regional weather/events/growth and independent all-vehicle separation on every 50 ms tick. Every service made additional calls in both 1,800-second windows. Six checkpoints validated economy, fleet and region, round-tripped the save library and verified that pause does not advance state. The run took **33.26 seconds** on an Apple M4 Max while regression tests ran concurrently. Accounts reconciled to **$131,040 revenue, $29,074 expenses and $101,966 operating profit**.
- Node heap samples and headless wall time are included in the report for reproducibility. They are neither GPU measurements nor proof of a one-hour real-time browser memory plateau. The existing swept/sub-tick safety regression remains unchanged.
- The production Worker served the local `/` route with HTTP 200. This checks server startup and response generation, not WebGL rendering or interaction.

## Remaining release acceptance and next steps

1. **Browser walkthrough:** tutorial controls, real save/import/export/download behavior, IndexedDB recovery, all four challenges, each quality/time/weather mode, grown towns, follow/trackside/photo cameras and office keyboard traversal. Record console errors and screenshots. The optional browser-testing request in this implementation has not received a response; no browser interaction or visual acceptance is claimed.
2. **Device matrix:** desktop Safari/Chrome and a real touch device, small portrait/landscape viewports, 200% text enlargement, reduced motion and color-independent signals. Export performance samples for overview, close follow and the busiest junction. Treat 60 FPS desktop/30 FPS low as provisional until target hardware is agreed and measured.
3. **Real-time soak:** sixty minutes including construction, teardown/remount, file loads, quality changes, pause/resume, background tabs, asset failure and forced WebGL context loss/restoration. Inspect retained GPU resources after cleanup. Optimize only the measured bottleneck; a worker migration and extra effects remain conditional.
4. **Player balancing:** record a first-time player's campaign and challenge attempts, including confusing steps, first delivery time, profitable routes and maintenance pressure. Existing deterministic completions establish feasibility. They do not justify new difficulty multipliers or certify usability; campaign costs and scenario rules are preserved until this evidence exists.
5. **Independent physical-system review and final publication smoke test** remain open. No independent-review result or browser/GPU pass is inferred from automated tests.

This delivers the Phase 7 runtime hardening work. The game is not yet certified release-ready while the acceptance items above remain open.
